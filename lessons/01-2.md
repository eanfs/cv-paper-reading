### 原文要点（摘自中文译文）

**§2 数据集：ILSVRC 长什么样、输入怎么处理**

> ImageNet 数据集有超过 1500 万的标注高分辨率图像，这些图像属于大约 22000 个类别。……ILSVRC 使用 ImageNet 的一个子集，1000 个类别每个类别大约 1000 张图像。总计，大约 120 万训练图像，50000 张验证图像和 15 万测试图像。

> ILSVRC-2010 是 ILSVRC 竞赛中唯一可以获得测试集标签的版本，因此我们大多数实验都是在这个版本上运行的。……在 ImageNet 上，按照惯例报告两个错误率：top-1 和 top-5，top-5 错误率是指测试图像的正确标签不在模型认为的五个最可能的标签之中。

> ……我们将图像进行下采样到固定的 256×256 分辨率。给定一个矩形图像，我们首先缩放图像短边长度为 256，然后从结果图像中裁剪中心的 256×256 大小的图像块。除了在训练集上对像素减去平均活跃度外，我们不对图像做任何其它的预处理。因此我们在原始的 RGB 像素值（中心的）上训练我们的网络。

**§3.1 ReLU：为什么不用 tanh / sigmoid**

> 将神经元输出 f 建模为输入 x 的函数的标准方式是用 f(x) = tanh(x) 或 f(x) = (1 + e^{−x})^{−1}。考虑到梯度下降的训练时间，这些饱和的非线性比非饱和非线性 f(x) = max(0,x) 更慢。……我们将这种非线性神经元称为修正线性单元(ReLU)。采用 ReLU 的深度卷积神经网络训练时间比等价的 tanh 单元要快几倍。

> 图1：使用 ReLU 的四层卷积神经网络在 CIFAR-10 数据集上达到 25% 的训练误差比使用 tanh 神经元的等价网络（虚线）快六倍。……这幅图表明，如果我们采用传统的饱和神经元模型，我们将不能在如此大的神经网络上实验该工作。

**§3.2 多 GPU：把网拆到两张卡上**

> 单个 GTX580 GPU 只有 3G 内存，这限制了可以在 GTX580 上进行训练的网络最大尺寸。事实证明 120 万图像用来进行网络训练是足够的，但网络太大因此不能在单个 GPU 上进行训练。因此我们将网络分布在两个 GPU 上。……基本上每个 GPU 放置一半的核（或神经元），还有一个额外的技巧：只在某些特定的层上进行 GPU 通信。这意味着，例如，第 3 层的核会将第 2 层的所有核映射作为输入。然而，第 4 层的核只将位于相同 GPU 上的第 3 层的核映射作为输入。

> ……与每个卷积层一半的核在单 GPU 上训练的网络相比，这个方案分别降低了我们的 top-1 1.7%、top-5 1.2% 的错误率。双 GPU 网络比单 GPU 网络稍微减少了训练时间。

> 图2：……网络的输入是 150,528 维，网络剩下层的神经元数目分别是 253,440–186,624–64,896–64,896–43,264–4096–4096–1000（8 层）。

### 白话解释

这三节回答同一件事：**数据够大、训练够快，才能把这么深的网训起来。**

**1. 数据（§2）**  
ImageNet 全库约 2.2 万类、超过 1500 万张图；竞赛子集 ILSVRC 是 **1000 类**，约 **120 万训练 / 5 万验证 / 15 万测试**。多数实验跑在 **ILSVRC-2010**（测试标签公开）；第六节才报 **ILSVRC-2012**。评测习惯用 **top-1** 和 **top-5** 错误率。

输入要固定尺寸：先把短边缩到 256，再裁中心 **256×256**；预处理只做 **减训练集像素均值**，其余直接用中心化后的原始 RGB。后面训练时还会从 256 里再裁 224×224（见第 4 课数据增强），所以图 2 写的输入维是 \(224×224×3 = 150{,}528\)。

**2. ReLU（§3.1）与图 1**  
旧习惯用 **tanh / sigmoid**，两端会「饱和」——梯度变小，大网难训。作者改用  
\(f(x)=\max(0,x)\)，即 **ReLU**（非饱和）。在 CIFAR-10 上一个四层 CNN 达到 25% 训练误差，ReLU 比等价 tanh 网 **快约六倍**；作者说：若仍用饱和神经元，根本做不了这篇规模的实验。要点是 **学得快**，不是 Caltech 那种「防过拟合」叙事。

**3. 双 GPU（§3.2）与图 2**  
单卡 GTX 580 只有 **3GB**，网放不下；于是 **每张卡放一半的核**，且 **只在部分层互通**：例如第 3 层看第 2 层全部核图，第 4 层只看本卡上的第 3 层核图——用交叉验证调「通信量 vs 计算量」。相对「每层核数减半、单卡训」的基线，双卡方案再降 **top-1 1.7%、top-5 1.2%**，训练时间还略短一点。图 2 画出上下两列（两块 GPU）以及八层神经元数。

架构小节按作者自评重要性排序：**3.1–3.4 里最重要的先讲**，所以 ReLU、多 GPU 排在 LRN、重叠池化前面。

### 当时要解决什么？对后续有何影响？

- **要解决的（据 §2–3.2）**：在 ILSVRC 百万级数据上，把输入统一成可训的固定分辨率；用 **ReLU** 把大网的训练时间压到可接受；用 **双 GPU + 受限跨卡连接** 突破单卡 3GB 显存，同时比「半核单卡」更准。  
- **文中已写明的影响线索**：没有 ReLU 就「不能在如此大的神经网络上实验」；双 GPU 相对半核单卡有明确的 top-1 / top-5 降幅。后续课的 LRN、重叠池化、整体层宽都建立在「已经训得动」这一前提上。

### 思考题

1. 预处理只有「短边→256 → 中心裁 256×256 → 减均值」。作者为什么强调「在原始 RGB（中心化）上训练」？这和当时常见的复杂手工特征管线差在哪里？  
2. 图 1 的「快六倍」测的是 CIFAR-10 上达到 25% **训练误差** 的迭代次数，不是 ImageNet 测试精度。作者据此推断「没有 ReLU 就做不了大网实验」——这个外推成立的前提是什么？  
3. 双 GPU 相对「每层一半核、单 GPU」降了 top-1 1.7%。多出来的收益，更像是「参数 / 容量翻倍」，还是「跨卡通信带来的特殊连接模式」？文中给了哪些证据可以区分？
